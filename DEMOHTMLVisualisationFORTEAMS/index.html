Core Architecture Principle: Read-Only Source Systems
Monkspaces does NOT perform direct write-back into client ERP (SAP S/4HANA) or PLM (Trace One Devex). Data quality gaps generate Source Correction Tickets. Corrections must be approved and applied in the client's authoritative source system before initiating a clean re-import.
01

Source File & Export Collection Read-Only

Product masters, BOM packaging specifications, material composition sheets, and market sales volumes are collected via Excel/CSV uploads or read-only staging connectors.

Lineage & Evidence
Original file hash (SHA-256) recorded. Stored in tenant-scoped private object storage under immutable retention policy.
02

Batch Ingestion & File Health Checks Staging

Upload files are parsed; header structures and encoding are verified. Batch record created in ingestion_batches with row counts and uploader metadata.

Audit Checkpoint
Unmapped raw records preserved in raw_staged_records (JSONB) to guarantee zero data loss.
03

Column Mapping & Unit Normalization Human-in-the-Loop

Source columns mapped to canonical Data Points (DP01–DP45) using reusable mapping_templates. AI suggests mappings with confidence score; unit transformation converts (e.g. kg to g).

Governance Gate
Requires user confirmation for low-confidence fields. Mapping template versioned for future supplier feeds.
04

Shared Canonical Data Foundation Layer 1

Normalized entities populated into products, packaging_components (BOM tree), component_materials_split, and sales_placed_on_market.

Single Source of Truth
Reusable across EPR, future PPWR, and DPP modules. No regulatory fee rules are baked into canonical tables.
05

Data-Quality Engine & Gap Resolution Layer 2

Evaluates canonical data against jurisdiction rules matrix (compliance_data_point_rules). Flags missing weights, unverified PCR %, and material ambiguity.

Financial Impact Ranking
Issues ranked by € money-at-risk. Classifies into BLOCKERS (prevents submission) vs WARNINGS (uncertainty margin).
06

Source Correction & Re-Import Loop Workflow

Issues generate source_correction_tickets (e.g. Devex spec 12.0g != supplier 10.5g). Correction approved and routed to client ERP/PLM team. Re-import updates foundation cleanly.

Traceability
Before/after values, actor, timestamp, reason, and supplier evidence reference preserved for audit.
07

Four-Eyes Review & Locked Baseline Snapshot

Consultant and client reviewer conduct four-eyes signoff. Data frozen into immutable locked_snapshots with completeness % and fee uncertainty amount.

Immutability Principle
Subsequent product changes or ERP updates will never retroactively modify a locked compliance period.
08

EPR Regulatory Fee Calculation Layer 3

Reads locked snapshot; applies versioned jurisdiction tariffs (e.g. UK PackUK illustrative 2026/27) and RAM RAG modulation multipliers (e.g. 1.2x Red malus).

Line-Item Traceability
Formula preserved per row: Units x Weight = Tonnage x Base Tariff x Multiplier = Line Fee.
09

Regulatory Submission Export Output

Generates official government-ready submission files: UK Defra RPD CSV (LP submission format), France Citeo declaration, and fee reconciliation summaries.

Schema Compliance
Aggregated into packaging activities (SO, PF, IM), packaging types (HH, NH), classes (P1, P3), and materials.

Architecture & Schemas
1. Multi-Tenant Isolation Across All Tiers CRITICAL

Monkspaces consultants manage multiple client workspaces (e.g. Kraft Heinz and competitors). A single missing tenant filter in an API, query, search index, or export could leak proprietary packaging formulas or commercial sales volumes.

Architecture Review Finding Enforce tenant_id scoping at route dependency, ORM query, and private S3 bucket paths. Implement PostgreSQL Row-Level Security (RLS) as mandatory defense-in-depth. Frontend filtering alone is unacceptable.
2. Unknown Values Must Never Silently Default to Zero CRITICAL

If an empty packaging component weight is missing in PLM, treating it as 0.0 grams would result in an illegal underpayment of national EPR fees to Defra / Citeo. Similarly, assuming unverified PCR % is 30% creates plastic tax fraud risk.

Architecture Review Finding Keep columns nullable (weight_grams NUMERIC NULL). Null weights trigger a BLOCKER in the data-quality engine and flag the fee uncertainty band rather than defaulting to zero.
3. Field-Level Source Lineage & Evidence Traceability HIGH

Regulatory audits by environmental agencies (Defra, Ademe) require proving the empirical origin of every recycled content percentage and weight measurement.

Architecture Review Finding Link components to evidence_document_id (supplier test certs, ISO declarations) and preserve the originating batch ID, row number, and source system in packaging_components and calculation traces.
4. Specification & BOM Versioning Drift HIGH

Packaging designs evolve (e.g. lightweighting a ketchup bottle from 24g to 22g). If the platform directly calculates fees from live mutable product records, historical 2025 filings will be corrupted by 2026 design changes.

Architecture Review Finding Implement locked_snapshots. Compliance calculation runs link strictly to immutable snapshot IDs, freezing the exact BOM state and sales volume used during regulatory filing.
5. Controlled Material Taxonomy & Composite Splits HIGH

Multi-material packaging (e.g. retort pouch with PET outer, Aluminium barrier, PP sealant) cannot be represented by a single "plastic" field without failing eco-modulation rules.

Architecture Review Finding Utilize component_materials_split relational table to model exact layer percentages (e.g. 45% PET / 15% Alu / 40% PP). Enforce standard polymer taxonomy (DP07: PET, HDPE, PP, LDPE).
6. Mapping Template Governance & AI Confirmation MEDIUM

Supplier spreadsheets frequently change column names (e.g. 'Wt (g)' vs 'Weight_kg'). Auto-applying AI column mappings without human confirmation can cause massive scale errors (1000x difference between kg and grams).

Architecture Review Finding Store confidence_score and is_user_confirmed in mapping_template_fields. Require explicit user signoff whenever unit conversion (KG_TO_GRAMS) is inferred.
7. Versioned Regulatory Tariffs & Multipliers HIGH

EPR fee schedules (e.g. UK PackUK illustrative rates, RAM guidance) change annually. Hardcoding tariffs into backend calculation logic prevents reproducing prior year filings.

Architecture Review Finding Store tariff schedules in jurisdiction_rule_sets with effective date ranges and versions (e.g. 'PackUK 2026/27 · RAM v1.1'). Each calculation run records the exact rule version applied.
8. Data Quality Lifecycle vs Compliance Status MEDIUM

A record can be 100% complete (no missing fields) but legally non-compliant (e.g. contains banned PFAS or non-recyclable carbon black pigment). Conflating quality and compliance creates user confusion.

Architecture Review Finding Maintain separation: Layer 2 manages data completeness & consistency; Layer 3 evaluates regulatory legality and fee liability.
9. Permissive Staging vs Strict Relational Core MEDIUM

Strict database foreign keys on raw file upload will cause entire 50,000-row client spreadsheets to fail if one supplier code is unrecognised, frustrating enterprise users.

Architecture Review Finding Use a two-tier database strategy: Staging tier stores raw records in JSONB with loose constraints; canonical tier enforces strict relational foreign keys after mapping and validation.
